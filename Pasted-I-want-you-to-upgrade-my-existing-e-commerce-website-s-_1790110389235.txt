I want you to upgrade my existing e-commerce website's Add to Cart, Checkout, Payment, and Order Confirmation system.

IMPORTANT:
Do NOT redesign or break the existing website. Keep the current UI, styling, products, cart, checkout flow, and navigation unless changes are necessary for this feature.

FEATURE I NEED:

When a customer adds products to the cart and proceeds to checkout:

1. CUSTOMER CHECKOUT
- Customer reviews their cart.
- Customer enters:
  - Full name
  - Email address
  - Phone number
  - Delivery address
  - Any other information already required by the existing checkout.
- Display the complete order summary:
  - Products
  - Quantities
  - Individual prices
  - Subtotal
  - Delivery fee (if applicable)
  - Total amount

2. PAYMENT
- Connect the existing payment system already used by the website.
- DO NOT mark an order as "Paid" simply because the customer clicks the payment button.
- The order must only be marked as "Paid" after the payment provider confirms successful payment.
- Use the payment provider's webhook/payment verification mechanism where available.
- Make sure payment verification happens securely on the server/backend.

3. AFTER SUCCESSFUL PAYMENT
Once payment has been successfully verified:

Create an order record containing at least:

- Order ID
- Customer name
- Customer email
- Customer phone
- Delivery address
- Products ordered
- Quantities
- Total amount
- Payment status
- Order status
- Payment reference/transaction ID
- Date and time
- Producer/seller associated with the product

Set:

Payment Status = "Paid"
Order Status = "Accepted" or "Confirmed"

IMPORTANT:
The order confirmation notifications must ONLY be sent after successful payment verification.

Structure the application so SMS notifications can also be enabled.

Create notification functions such as:

sendProducerSMS()

Use environment variables for SMS credentials.

Do NOT hard-code API keys, passwords, email credentials, payment secrets, or SMS credentials into the code.

7. EMAIL SERVICE

If the project already has an email service, use the existing service instead of creating another one.

9. PREVENT DUPLICATE ORDERS

This is very important.

Payment webhooks can sometimes be sent more than once.

Make the payment/order processing idempotent.

If the same payment reference is received again:
- Do not create another order.
- Do not send duplicate customer emails.
- Do not send duplicate producer emails.
- Simply return a successful response to the payment provider.

10. ERROR HANDLING

If payment succeeds but an email fails:

DO NOT reverse or mark the payment as failed.

Keep the order as Paid.

Record the notification failure in the database/logs and allow the notification to be retried.

13. SECURITY

Follow secure payment practices.

- Never trust payment status sent from the frontend.
- Verify payments server-side.
- Validate webhook signatures where supported.
- Never expose secret API keys in frontend code.
- Validate customer/order information.
- Prevent users from modifying the price or total amount through the browser.
- Calculate totals on the server.
- Use the payment provider's verified transaction amount when confirming payment.
- Prevent duplicate webhook processing.
